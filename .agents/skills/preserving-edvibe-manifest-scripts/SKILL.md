# Preserving Edvibe Runtime Entry Points

## Overview

Keep `manifest.json` focused on extension runtime wiring and let the source entry points express JavaScript dependency evaluation order. CRXJS/Vite owns the production transformation from source files to the committed `dist/` extension.

## Required invariants

| Runtime | Required wiring |
|---|---|
| Popup | `popup.html` loads `src/entrypoints/popup.js` as its module entry point. |
| `ISOLATED` | `manifest.json` loads `src/entrypoints/isolated.js` at `document_start`. |
| `MAIN` | `manifest.json` loads `src/entrypoints/main.js` at `document_start`. |
| Standalone content scripts | Every manifest content-script entry point remains listed in CRXJS `contentScripts.standaloneFiles`, especially the timing-sensitive MAIN-world entry. |

Keep entry points as small composition roots. `src/entrypoints/main.js` registers components that must exist before the MAIN coordinator and imports `src/runtime/main.js` last. The isolated and popup entry points import their runtime coordinators from `src/runtime/` after any entrypoint-owned registrations.

Production paths under `dist/` are generated by `npm run build`. Never repair runtime wiring by editing generated JavaScript, generated manifests, or copied stylesheets directly.

## Workflow

1. Read `manifest.json`, `vite.config.mjs`, and the relevant `src/entrypoints/*.js` file before editing runtime wiring.
2. Keep one source entry file per content-script world in the manifest and preserve `document_start` where configured.
3. Add or move JavaScript dependencies in the relevant source entry point, after their dependencies and before their consumers.
4. Preserve standalone CRXJS output for timing-sensitive content-script entries.
5. Keep popup module wiring in `popup.html` and `src/entrypoints/popup.js`.
6. Run the repository CI validation, including the production build. Inspect generated output through the build, not by modifying `dist/`.

## Example

```json
{
    "js": ["src/entrypoints/isolated.js"],
    "run_at": "document_start",
    "world": "ISOLATED"
},
{
    "js": ["src/entrypoints/main.js"],
    "run_at": "document_start",
    "world": "MAIN"
}
```

```js
// src/entrypoints/main.js
import '../components/export-progress-dialog.js';
import '../components/reset-lessons-dialog.js';
import '../runtime/main.js';
```

## Common mistakes

| Mistake | Required correction |
|---|---|
| Put module implementation dependencies into manifest content-script wiring | Import them from the relevant source entry point instead. |
| Remove a timing-sensitive content script from CRXJS standalone output | Restore standalone output so `document_start` execution remains reliable. |
| Load a runtime coordinator before entrypoint-owned registrations it depends on | Keep dependency initialization and feature registration before the coordinator import. |
| Patch generated files under `dist/` | Change source or build configuration and rebuild. |
| Copy a runtime library into the repository | Add or update the npm dependency and import it from source so Vite bundles it. |
